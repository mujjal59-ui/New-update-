# PROMPT 2 — LXR--AI SIX-PROJECT INTEGRATION (A–F)

Proceed only after I have reviewed and explicitly approved the Phase 1 compatibility report.

Integrate the following systems into my existing LXR--AI Android project using the safest compatible architecture.

## A. Video Creation Infrastructure

1. OpenMontage — primary video production workflow for scene composition, animation, editing and rendering.
2. FreeLLMAPI — unified LLM gateway, provider fallback and quota tracking.
3. OmniRoute — alternative provider routing and model access.

Use dedicated backend adapters for each system. Installing a GitHub repository does not mean its APIs are integrated. Verify actual endpoints, authentication and working functionality.

## B. Search & Research

Keep Google Search as the primary search provider.

Add Perplexity, You.com and Phind only when a currently supported, working API integration is verified.

Use these services for:
- Research
- Fact verification
- Comparing information from sources
- Providing source links

Do not use research providers as video-generation engines.

## C. Free Token Management

Preserve the FreeLLMAPI setup described in the uploaded PDF, subject to compatibility and actual provider availability.

Requirements:
- Configure supported free provider API keys securely.
- Use provider routing and fallback where supported.
- Track actual token consumption by provider.
- Show actual remaining quota only when the provider reports it.
- Handle rate limits and temporary failures with safe fallback.
- Avoid duplicate upstream requests across gateways.
- Show provider status and usage accurately.
- Never fabricate token balances or quotas.
- Treat 7.4B monthly tokens as an aggregate published estimate, not guaranteed personal entitlement.
- Do not use paid providers without my explicit approval.
- Pause and notify me when free capacity is exhausted.

## D. Preserve Existing Google Voice Integration

Do not remove, rename, replace or break any existing Google voice.

Preserve:
- Aoede
- Iapetus
- Leda
- Orus
- Achernar
- Charon
- Sulafat

Reuse the existing voice-selection and audio-generation system for narration or character dialogue only where technically compatible.

## E. Real Video Generation

Connect OpenMontage to actual supported video and media providers.

Where supported, enable:
- Text-to-video
- Image-to-video
- Character animation
- Voiceover and dialogue
- Scene composition
- Video editing
- Final MP4 rendering and export

Do not claim genuine AI video generation if the implementation only creates a slideshow, static images, zoom or pan effects.

Track LLM tokens, video credits, voice usage and rendering resources separately. LLM tokens must never be represented as video credits.

## F. Security & Compatibility

- Keep all provider API keys on the secure backend.
- Never hardcode secret keys in Android source code.
- Use authenticated backend endpoints.
- Preserve existing UI, features, voice settings and behavior.
- Make only the approved integration changes.
- Avoid unrelated refactoring or rewriting.
- Verify endpoints and test actual provider responses.
- Provide clear error handling and provider availability status.
- Do not use paid services without my explicit approval.

## Implementation and verification

Use the Phase 1 report as the implementation plan.

Implement each integration through isolated adapters and backend services. Keep the existing application working throughout the process.

Build and test the Android APK after implementation.

Report separately:
1. Successfully integrated and tested
2. Integrated but not fully tested
3. Requires API key or backend setup
4. Paid or quota-limited
5. Unsupported or unavailable
6. Remaining work

Do not mark any feature complete without a real test.

Do not make unrelated changes to my existing project.
